```cpp
static const JWPLC_UIMenuNode nodos[] = {
    JWPLC_UIMenuView(JWPLC_UI_MENU_ROOT, "Temperatura", &temperatura, 1, "C"),
    JWPLC_UIMenuEditNum(JWPLC_UI_MENU_ROOT, "Consigna", &consigna, 0.0f, 100.0f, 0.5f, 1, "C"),
    JWPLC_UIMenuEditBool(JWPLC_UI_MENU_ROOT, "Bomba", &bomba, "PARADA", "MARCHA"),
    JWPLC_UIMenuSubmenu(JWPLC_UI_MENU_ROOT, "Avanzado"),            // índice 3
    JWPLC_UIMenuEditNum(3, "Retardo", &retardo, 0, 600, 5, "s"),     // int32_t
};
static const JWPLC_UIMenu menus[] = {
    JWPLC_UIMenuField(MENU_AJUSTES, 10, 20, 300, 140, "Ajustes", nodos, 5, PAGE_AJUSTES)};

JWPLC_Display.setMenus(menus, 1);
if (JWPLC_Display.menuChanged(MENU_AJUSTES, &nodo)) { /* guardar en FRAM, etc. */ }
```

Decisiones:

| Tema | Decisión |
|---|---|
| Enlazado | El motor vive en su propio TU. `JWPLC_UI_API.cpp` trae hooks `jwplcUIMenu*` weak y el TU del MENU aporta los strong, así que sólo se enlaza si el sketch usa `setMenus`. Un sketch sin MENU cuesta +48 B de flash y +0 B de RAM. |
| ABI | No se agregan miembros de datos a ninguna clase. `JWPLC_DisplayClass` suma métodos no virtuales; los 0 símbolos globales eliminados se verifican con `regenerate_libJWPLC_Display.sh`. |
| Teclas (regla 5) | El MENU declara su dueño explícitamente: mientras su página está en PAGE_CONTENT (o si sólo hay una página) consume UP/DOWN/LEFT/RIGHT/OK. ESC lo consume sólo fuera de la raíz o en edición; en la raíz queda para el sistema (vuelve a PAGE_SELECT). En PAGE_SELECT no toca la botonera. |
| Repetición | La edición usa `JW_MatrixButtons::applyAxis()`, que trae la auto-repetición acelerada existente. LEFT/RIGHT mueven ±10 pasos. |
| Escritura | Sólo al confirmar con OK; ESC descarta. Al cambiar de página se cancela la edición. Los límites se aplican en el equipo. |
| Bus SPI (regla 1) | `serviceInput()` no toca la TFT. Todo el dibujo ocurre en `jwplcUIRuntimeDrawStatic/DrawDirty`, con el bus tomado. |
| Dirty (regla 2) | Marco y título al entrar a la página o cambiar de nivel. Al mover la selección se repintan 2 filas. Una fila VIEW se repinta sola cuando cambia su variable (sondeo en el tick, sin TFT). |
| Foco | En PAGE_SELECT la fila seleccionada se dibuja sólo con contorno; en PAGE_CONTENT, rellena. |
| Límites | 4 menús, 64 nodos por menú, profundidad 3, 16 filas visibles, 1 menú por página. `setMenus()` rechaza: padre declarado después, profundidad > 3, variable nula, `max < min`, IDs repetidos. |

## Designer `[ejecutado]`

- `poc/designer-menu.js`:
  - modelo (árbol plano con `parent` por clave, copy-on-write);
  - pintor que replica `drawFull()/drawHeader()/drawRow()` del firmware;
  - codegen puro (`generate(menus, context)`);
  - inspector.
- Herramienta "Menú de configuración (MENU)" en el desplegable de variables. Un MENU por página.
- Inspector:
  - **Diseño**:
    - Forma: tamaño 1×/2×, marco;
    - Contenido: título;
    - Apariencia: 10 colores con paleta;
    - Ubicación: página, X/Y, ancho y alto.
  - **Árbol y datos**:
    - agregar Submenú / Ver / Editar nº / Editar ON/OFF;
    - subir, bajar y eliminar;
    - editor del ítem: texto, variable, tipo float/int32_t/bool, unidad, decimales, mínimo/máximo/paso, textos ON/OFF, valor inicial;
    - "ver como editando".
  - **Técnico**: nombre, ID, ejemplo `menuChanged()`, diagnóstico (nodos, profundidad, RAM, problemas).
- El "+ Submenú" se deshabilita donde el submenú quedaría en el nivel 3.
- El lienzo muestra el nivel del ítem elegido en el árbol.
- Codegen:
  - `#ifndef JWPLC_UI_HAS_MENU` → `#error` claro con un package anterior;
  - `enum HMIMenuId`;
  - índices de nodo simbólicos (`MENU_AJUSTES_CONSIGNA`) para el `switch` de `menuChanged()`;
  - variables con su tipo y valor inicial (sin redeclarar las de los campos);
  - errores de validación como `#error`.
- `tests/menu-smoke.cjs`:
  - crea el MENU con la herramienta y opera el inspector;
  - verifica undo, guardar/abrir y el límite de profundidad;
  - compara píxel a píxel el lienzo con el framebuffer del firmware simulado en 3 estados: 0 diferencias;
  - compila el header con g++ y verifica los símbolos en el `.a`.

### Correcciones de paso

- `designer-codegen.js`: el marcador `// Sincronización gráfica autogenerada.` (con punto) no coincidía con el texto emitido. Una segunda pasada sobre un header sin gráfica estática duplicaba `jwplcUIUpdate()`. Pasaba al hacer clic en "Contrato" con un diseño sólo de campos.
- `designer-inspector-state.js` mostraba el inspector de campos para cualquier tipo desconocido; ahora tiene el modo MENU.
