## Placas y conexionado

| Placa | USB | Periféricos y función |
| --- | --- | --- |
| **JWPLC Basic principal** | **COM4** | Master RTU, RJ45 Ethernet W5500, microSD, RTC, FRAM, TFT, botonera, Modbus TCP Server Unit 1 puerto 502, UDP 15020 |
| JWPLC Basic secundario **opcional** | **COM14** | Slave RTU ID 2, 115200 8N1, los 4 holding registers conocidos del gate G8 |

COM4 solamente permite comprobar TCP, UDP, SD, FRAM, RTC y runtime autoload; **no permite acreditar Modbus RTU Master↔Slave real**. Para convivencia Ethernet y RTU en paralelo se recomiendan las dos placas, con P↔P y N↔N (P=A, N=B), masas/terminaciones/bias conforme al banco y sin tensiones ajenas en A/B.

Conectar el RJ45 de COM4 a **router/switch con DHCP**, en la misma red que el PC (la prueba usa la IP anunciada y TCP puerto 502, UDP 15020). La conexión directa al PC no dará IP DHCP salvo que el PC provea DHCP. La red debe ser de pruebas, no la de una máquina. Permitir estos puertos en el firewall si fuese necesario. Insertar microSD en COM4 antes de encender y mantenerla colocada.

Ambos JWPLC deben alimentarse desde banco seguro, **sin actuadores ni cargas en Q**, ni entradas con potencia industrial. Cerrar Arduino IDE/Serial Monitor y cualquier software que tome COM4/COM14. El upload cambia firmware de diagnóstico; **no hay backup/restauración automática** de los sketches previos.

## Ejecución simplificada Windows PowerShell

Desde el repositorio `platform-jwplc` existente (sin tocar su worktree actual):

```powershell
git fetch origin
git worktree add --detach "$env:TEMP\jwplc-g10h-a13" origin/codex/alpha13-g10-h-physical-com4-com14
cd "$env:TEMP\jwplc-g10h-a13"
.\tools\alpha13\gates\run_a13_g10_h_physical.bat --rtu
```

**En modo un solo JWPLC**, omitir `--rtu` (no abre ni programa COM14). La carpeta de worktree de ejemplo debe estar libre; si ya existe, crear una nueva con otro sufijo. `git fetch` no hace checkout ni pull del worktree activo. **No ejecutar `git clean`, `reset`, merge ni rebase para preparar el banco.**

Requisitos comprobados por el ejecutor: Windows, `python` con `pyserial`, `arduino-cli` **1.5.1** en PATH, toolchain instalado, placa con CH340 `VID=1A86 PID=7523`, rama fuente remota/HEAD coincidentes, working tree tracked limpio, hashes congelados y compilación contra `jwplc_local:esp32:jwplcbasic`. No reinstala Arduino IDE ni altera la configuración global de Arduino CLI; crea un sketchbook y configuración **temporales**.

El BAT primero verifica/compila **sin flash**. Después pide exactamente:
`G10H AUTORIZO FLASH COM4 COM14` (con `--rtu`) o `G10H AUTORIZO FLASH COM4` (modo uno). Si no se introduce la frase exacta, no hay upload. Si se autorizan dos, carga **primero COM14** y luego COM4. Cualquier fallo de preparación detiene antes del upload.

Durante unos 40 segundos el PC lee FC03 de 4 HR en Modbus TCP, envía datagramas UDP y verifica echo exacto. El COM4 sondea SD raíz read-only, RTC, FRAM dirección 0, pulsaciones de botonera y, si se incluye COM14, realiza solicitudes RTU FC03 concurrentes al Slave. **Pulsar y soltar una tecla física de COM4** cuando la consola lo indique.

## Criterios

- N0: procedencia de HEAD/source-first, configuración aislada, los cinco precompilados intactos; no usar otro core/librería ni archivo stale.
- N2 local: compilación candidato COM4 y Slave COM14 cuando corresponda, plataforma completa staged, objeto `JWPLC_W5500_SafeAccess.cpp.o`, archivo `.d`, ELF y bibliotecas seleccionadas.
- H: `ETH=1`, `TCP=1`, al menos 12 heartbeats y al menos 8 FC03 TCP correctos, 8 ecos UDP correctos; SD y FRAM leídos reiteradamente, RTC válido, 1 press/release. En modo dual al menos 8 FC03 RTU correctos sin fallos, y `REQUESTS>=8`/`CRC=0` en Slave COM14.
- `REVIEW_STOP` si hay pérdida de puerto, latidos insuficientes, falta de respuesta TCP/UDP/RTU, CRC/fallas, root SD o RTC inválidos, o ausencia de pulsación. No reportar PASS por compilar o por simular.
- Los registros PLC nunca se usan para accionar hardware; la prueba Modbus es **solo FC03**, sin escritura de coils ni salidas Q.
- No incluye medición explícita de reset físico, pérdida de cable, DNS público exitoso, pruebas EMC, tráfico industrial prolongado ni recuperación de energía. Estas verificaciones requieren etapa autorizada separada tras el smoke inicial.
