# Alpha14 — RTU-H2 — Sweep de gap a 500 kbaud

Fecha: 2026-09-26

## Objetivo

Caracterizar el piso tecnico del frame gap con el baudrate mas rapido validado
hasta H1B:

```txt
BAUD=500000
CONFIG=8N1
MOTOR=ASYNC
TX=QUEUED
TCP=OFF
FULL_RUNTIME=ACTIVE
RS485=A/B/GND
```

H1B confirmo 500000 exactos y completamente limpios a 500 us.

## Contexto temporal

A 500000 8N1:

```txt
1 caracter = 10 bits / 500000 = 20 us
3.5 caracteres fisicos = 70 us
```

Esto NO cambia la referencia normativa Modbus para baudrates altos. Los puntos
por debajo de la referencia conservadora se estudian exclusivamente para el
perfil futuro JWPLC_FAST, donde controlamos ambos extremos.

## Sweep

| Comando | Gap |
|---|---:|
| O | 500 us |
| W | 300 us |
| 1 | 200 us |
| 3 | 150 us |
| 4 | 100 us |
| T | 75 us |
| ! | 50 us |

Cada punto se mide durante 30 s con RTU unpaced y TCP OFF.

## Criterio

El control de 500 us debe quedar limpio.

Los puntos agresivos pueden fallar sin abortar el sweep; se registran:

- requests iniciadas/completadas/exitosas;
- fallos;
- timeout;
- CRC Master/Slave;
- throughput RTU;
- runtime/perifericos.

El runner informa:

```txt
RTUH2_LOWEST_CLEAN_GAP_US
RTUH2_FASTEST_CLEAN_GAP_US
RTUH2_FLOOR_WITHIN_SCOPE
```

Si 50 us sigue limpio:

```txt
RTUH2_FLOOR_WITHIN_SCOPE=NOT_FOUND_AT_OR_ABOVE_50US
```

y no se baja automaticamente de 50 us.

## Siguiente gate

H2 solo localiza el piso con TCP OFF. Luego H2B confirmara un conjunto reducido
de candidatos con TCP500 y elegira un valor con margen para la matriz
JWPLC_FAST/AUTO. El gap minimo absoluto no se convierte directamente en default.

## Gate versionado

El gate:

1. exige que el unico tracked dirty siga siendo el core candidato conocido;
2. oculta temporalmente el archive RTU precompilado;
3. compila y sube Master/Slave una sola vez desde source;
4. verifica `JWPLC_ModbusRTU.cpp.o` y `JWPLC_RS485.cpp.o` en ambos builds;
5. restaura el archive anterior con el mismo SHA-256;
6. ejecuta los siete gaps sin recompilar;
7. pide confirmacion fisica de ambas TFT;
8. verifica al cierre core, archive, dirty scope e indice.

La salida del runner se muestra en vivo y se guarda en log mediante
`python.exe -u` + `Tee-Object`.
