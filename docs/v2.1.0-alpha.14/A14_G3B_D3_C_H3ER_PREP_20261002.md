# Alpha14 — G3B-D3-C H3E-R prep — 2026-10-02

## Objetivo

Validar D3 load-adaptive durante el H3E-R completo:

```text
TCP FC03/125 = 1000 req/s
duration = 120 s
RTU = 50 Hz
DataLog = activo
Display/TFT = activo
FRAM/RTC/TCA-I-O/botonera = activos
SPI probe = activo
```

## Build candidato

El package conserva:

```text
JWPLC_MODBUS_TCP_INT_GUIDED_RX=0
JWPLC_MODBUS_TCP_INT_HOT_POLL_US=0
JWPLC_MODBUS_TCP_INT_LOAD_ADAPTIVE=0
```

Sólo el Master del gate se compila con:

```text
-DJWPLC_MODBUS_TCP_INT_GUIDED_RX=1
-DJWPLC_MODBUS_TCP_INT_LOAD_ADAPTIVE=1
```

No se activa el profile hook de D3 para no añadir instrumentación al hot path
del full-runtime.

## Infraestructura

Se reutiliza el H3E-R current-package ya cualificado. Se amplía únicamente su
lista de overrides admitidos para reconocer el candidato D3 exacto y comprobar
en el compile log que el flag load-adaptive fue realmente usado.

## Criterio

El gate H3E-R mantiene sus guards existentes de:

- 120000/120000;
- rate >= 99.9 %;
- cero errores TCP;
- RTU 49.5..50.5 Hz, cero skips/fails/CRC/timeouts;
- DataLog sin failed commits;
- periféricos sin failures;
- TFT Master/Slave PASS;
- source-first linkage;
- P95/P99 dentro de los guards H3E-R.

Además debe mostrar:

```text
H3ER_VARIANT=D3_LOAD_ADAPTIVE
H3ER_INT_GUIDED_RX_BUILD=ON
H3ER_INT_HOT_POLL_US_BUILD=0
H3ER_INT_LOAD_ADAPTIVE_BUILD=ON
H3ER_INT_LOAD_ADAPTIVE_BUILD_FLAG=PASS
H3ER_INT_LOAD_ADAPTIVE_PACKAGE_DEFAULT=0
```

Un PASS de D3-C todavía no cambia el default. Después se compara su tail contra
C0 POLLING antes de decidir D3-D promoción.
