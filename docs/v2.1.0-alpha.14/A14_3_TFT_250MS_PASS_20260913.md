# Alpha14 A14.3 — TFT 250 ms / 4 Hz

Fecha: 2026-09-13

## Clasificación

```text
A14_3_TFT_250MS=PASS_PHYSICAL
TFT_250MS_VIABLE_GTE95=YES
NEXT=REFINE_MINIMUM_REFRESH_PERIOD
```

## Objetivo

Medir si un periodo de refresco USER de 250 ms (4 Hz) conserva una UI dinámica utilizable sin degradar el objetivo de 1000 req/s de Modbus TCP.

El perfil mantuvo:

- full runtime integrado;
- Display inicializado y refresco dinámico activo;
- `DISPLAY_PERIOD_MS=250`;
- FRAM, RTC, I/O, botonera y SPI probe activos;
- Ethernet y Modbus TCP activos;
- microSD inicializada y lista;
- workload periódico SD fuera del scheduler para aislar únicamente la política TFT.

## Conclusión

250 ms / 4 Hz recupera prácticamente todo el rendimiento perdido por el refresco TFT a 100 ms, sin errores de TCP ni periféricos y manteniendo el refresco dinámico activo.

La hipótesis de cuello dominante en la política de refresco Display queda reforzada. El siguiente paso no es retirar Display ni modificar su autoload, sino encontrar el menor periodo que siga cumpliendo rendimiento y mantenga una experiencia visual adecuada.

El siguiente punto de prueba será 150 ms (~6.67 Hz):

- si mantiene ambas corridas >=95 %, se podrá seguir bajando el periodo;
- si no, el siguiente punto será cercano a 200 ms;
- la decisión final deberá considerar rendimiento y calidad visual.

```text
FINAL_DISPLAY_POLICY=NOT_DECIDED
NEXT_GATE=TFT_150MS
FINAL_30MIN_SOAK=ON_HOLD
```
