# Alpha14.3 — TFT 150 ms: resultado parcial

Fecha: 2026-09-13

Rama: `v2.1.0-alpha.14/feature/modbus-tcp`

## Objetivo

Refinar el periodo mínimo de refresco dinámico de la TFT que mantenga el rendimiento de Modbus TCP dentro de una zona segura en el perfil `FULL_RUNTIME_REALISTIC`.

Condiciones:

- Modbus TCP FC03 / 125 registros.
- 1000 req/s solicitadas.
- 2 corridas de 60 s.
- Full runtime activo.
- Display activo.
- Refresco TFT a 150 ms (~6.67 Hz).
- SD inicializada/autoload intacto.
- Workload periódico SD fuera del scheduler.
- FRAM, RTC, I/O, botonera y SPI probe activos.

## Clasificación

`PASS_DIAGNOSTIC`

Resultado de política:

`A14_3_TFT_150MS=TFT_150MS_PARTIAL`

## Interpretación

150 ms mejora claramente respecto a 100 ms y cruza 95 % en promedio, pero no es suficientemente robusto para adoptarse como política final porque una de las dos corridas cae a 94.163 % y el spread sube a 2.519 pp.

No hay evidencia de fallo funcional de TCP ni de periféricos. El límite observado sigue siendo de presupuesto temporal asociado a la cadencia de refresco TFT.

## Siguiente gate

Probar 200 ms / 5 Hz manteniendo el mismo aislamiento de SD.

Criterio principal: ambas corridas deben mantenerse en >=95 % con TCP/runtime/periféricos limpios.

Si 200 ms pasa con margen, se podrá evaluar 175 ms como refinamiento adicional. Si 200 ms no pasa de forma robusta, 250 ms permanece como candidato seguro conocido.
