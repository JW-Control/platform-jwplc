# Alpha14 — NB3-F2: cierre físico TCP legacy normal + backpressure

## Objetivo

Demostrar en hardware que `EthernetClient::write()` conserva el camino legacy bloqueante, funciona normalmente y deja de poder esperar indefinidamente bajo backpressure.

## Configuración

```text
WRITE_TIMEOUT_MS=250
NORMAL_WRITE_HOLD_LIMIT_US=50000
BACKPRESSURE_TIMEOUT_HOLD_MIN_US=150000
BACKPRESSURE_TIMEOUT_HOLD_MAX_US=450000
SPI=26 MHz
```

## Camino normal

```text
NORMAL_CONNECTED=YES
NORMAL_WRITE_CALLS=4
NORMAL_BYTES=4096
NORMAL_WRITE_HOLD_MAX_US=1765

PC_NORMAL_ACCEPTED=YES
PC_NORMAL_BYTES=4096
PC_NORMAL_PATTERN=PASS
```

## Backpressure real

El servidor PC acepta la conexión pero deliberadamente no consume datos.

```text
BACKPRESSURE_CONNECTED=YES
BACKPRESSURE_SUCCESSFUL_WRITES=5
BACKPRESSURE_BYTES=5120
BACKPRESSURE_SUCCESSFUL_HOLD_MAX_US=248791

BACKPRESSURE_TIMEOUT_OBSERVED=YES
BACKPRESSURE_TIMEOUT_WRITE_RETURN=0
BACKPRESSURE_TIMEOUT_HOLD_US=249397
BACKPRESSURE_CONNECTED_AFTER_TIMEOUT=YES

PC_BACKPRESSURE_ACCEPTED=YES
PC_BACKPRESSURE_RCVBUF=1024
```

La llamada que agotó el presupuesto retornó aproximadamente al timeout configurado de 250 ms y el socket seguía conectado. Esto distingue el timeout software de un cierre remoto.

## Convivencia SPI

```text
SPI_LOCK_ERRORS=0
VISUAL_SPI_EVENTS=0
```

## Resultado

