# Alpha14 — A14.3 PERF-S1 FC03 saturación sin espera

Fecha: `2026-09-12`

## Objetivo

Medir el techo observado del JWPLC Basic actuando como Modbus TCP Server con una sola conexión TCP persistente y FC03, eliminando el pacing entre requests.

Este ensayo corresponde a `PERF-S1` y mide el escenario TCP-only a nivel de aplicación. Los Mbps reportados son payload Modbus/TCP observado por la aplicación y no incluyen cabeceras Ethernet/IP/TCP ni ACKs.

## Configuración

```text
PC Master -> JWPLC Modbus TCP Server
FC03 Read Holding Registers
conexión TCP persistente
modo no-wait
10 s por tamaño
Unit ID=1
Port=502
```

Tamaños:

```text
1 register
16 registers
64 registers
125 registers
```

## Precondición de conexión

El harness fue ajustado para separar la fase de preparación de la ventana de benchmark:

1. esperar `SERVER_READY=YES`;
2. establecer la conexión TCP con retry de preparación;
3. reiniciar estadísticas después de conectar;
4. iniciar la ventana de saturación.

En la ejecución válida los cuatro casos conectaron en el primer intento:

```text
Q=1   CONNECT_ATTEMPTS=1
Q=16  CONNECT_ATTEMPTS=1
Q=64  CONNECT_ATTEMPTS=1
Q=125 CONNECT_ATTEMPTS=1
A14_3_TCP_CONNECT_PRECONDITION=PASS
```


## Interpretación

El mayor número de transacciones por segundo aparece con payload mínimo (`1 register`), mientras que el mayor throughput en Mbps aparece con el payload máximo FC03 (`125 registers`).

La prueba sin espera caracteriza un techo observado de corta duración. No define todavía la tasa industrial recomendada ni `SERVER_MAX_STABLE_REQ_S`.

El punto de 125 registros es el candidato principal para medir throughput máximo en Mbps y para comparar posteriormente:

```text
TCP_ONLY
FULL_RUNTIME_REALISTIC
FULL_RUNTIME_STRESS
RTU_TCP_COEX
```
