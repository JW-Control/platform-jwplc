Comparación contra batch 8:

| Variante | Delta TCP | Delta payload SPI | Delta hold promedio | Delta hold máximo | Fairness |
|---|---:|---:|---:|---:|---|
| Batch 16 | +13.762% | +0.176% | −8.110% | +84.099% | FAIL |
| Batch 32 | +12.125% | +0.119% | −7.106% | +252.939% | FAIL |

El throughput TCP fue muy variable y el payload de batch 8 superó el spread
máximo de 0.5%, por lo que P9 no establece una ganancia de velocidad
repetible. La señal de fairness sí fue estable: el hold máximo creció casi de
forma proporcional al batch.

## Decisión

Mantener batch 8. Batch 16 y 32 no se promocionan aunque 16 haya marcado el
mayor TCP mediano. La mejora de payload interno fue menor a 0.2%, mientras el
hold máximo aumentó 84.1% y 252.9%.

No se abre el experimento de topología RX 4/8 KB: P9 no muestra una limitación
de payload que justifique cambiar la distribución de sockets del W5500. El
frente RX queda mapeado y el siguiente trabajo pasa a TX async A2.
